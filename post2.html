Building an Agentic Travel Planner with MCP and LangGraph

AI agents are evolving rapidly from simple chatbot assistants into autonomous systems capable of orchestrating tools, APIs, and reasoning workflows. One of the most important standards enabling this shift is Model Context Protocol (MCP).

In this project, I built a modular AI travel planner that combines:

  • Weather intelligence
  • Flight search
  • Semantic hotel recommendation
  • LLM-powered itinerary generation
  • LangGraph workflow orchestration
  • MCP-based external services

The result is an end-to-end agentic workflow capable of generating complete travel plans from only a few user inputs.

What is MCP?

MCP (Model Context Protocol), introduced by Anthropic in 2024, standardizes how AI agents communicate with external tools and services.

Instead of tightly coupling API logic directly inside agents, MCP separates external services into reusable tool servers. This creates cleaner architectures and makes AI systems more modular and scalable.

In this project, MCP servers handle weather retrieval and flight search through separate external services exposed over SSE.

Project Architecture

The system is composed of multiple specialized agents:

  • WeatherAgent → Finds the best travel months
  • FlightAgent → Retrieves available flights
  • HotelAgent → Ranks hotels semantically
  • ItineraryAgent → Generates AI itineraries using Llama.cpp

The agents can be orchestrated either through a traditional SupervisorAgent or through a graph-based workflow using LangGraph.

LangGraph Workflow

Weather Node
    ↓
Flight Node
    ↓
Hotel Node
    ↓
Itinerary Node
    ↓
Final Travel Plan

LangGraph also makes the architecture easier to extend with retries, fallback nodes, branching logic, shared state management, and debug logging.

The workflow graph is built programmatically: 


graph.add_edge("weather", "flight")
graph.add_edge("flight", "hotel")
graph.add_edge("hotel", "itinerary")

Weather MCP Server

For weather intelligence, I used the OpenWeather API.

OpenWeather API Keys

The weather MCP server exposes weather functionality over SSE and allows agents to retrieve climate information without directly embedding API logic inside the agent itself.

Flight Search Challenges

One of the most difficult parts of the project was flight integration. Finding a flight API suitable for development and testing turned out to be more challenging than expected.

Initially, I explored using the Amadeus Flight API:

Amadeus Developers Portal

However, the free-tier limitations made real flight retrieval difficult during development and experimentation.

Because of this, I implemented a manual flight database and exposed it through an MCP server instead.

Even with a manual database, I was still able to fully test the MCP architecture, multi-agent orchestration, and LangGraph workflow while simulating realistic flight search behavior.

Semantic Hotel Search

One of the most interesting parts of the project was the hotel ranking system.

Instead of simple keyword matching, I used SentenceTransformers embeddings to compute semantic similarity between user preferences and hotel descriptions.

Example preferences: 

"mid budget hotel near city center with breakfast"

The ranking system combines semantic similarity with price compatibility into a final recommendation score.

Local LLM with Llama.cpp

For itinerary generation, I used Llama.cpp together with a GGUF-quantized Llama model running locally.

Running a local LLM provided offline inference, lower cost, full prompt control, and easier experimentation.

Why This Project Matters

Modern AI engineering is increasingly moving toward agent orchestration, tool calling, workflow systems, external service integration, and memory-driven architectures.

This project explores those ideas in a practical way by combining MCP, LangGraph, semantic search, local LLMs, and workflow orchestration into one modular AI system.

Instead of building a single chatbot, the goal was to experiment with how specialized agents can collaborate, share state, and interact with external tools through standardized protocols.
