Building an Agentic Travel Planner with MCP and LangGraph

AI agents are evolving rapidly from simple chatbot assistants into autonomous systems capable of orchestrating tools, APIs, and reasoning workflows. One of the most important standards enabling this shift is Model Context Protocol (MCP).

In this project, I built a modular AI travel planner that combines:

  • Weather intelligence
  • Flight search
  • Semantic hotel recommendation
  • LLM-powered itinerary generation
  • LangGraph workflow orchestration
  • MCP-based external services

The result is an end-to-end agentic workflow capable of generating complete travel plans from a few user inputs.

What is MCP?

MCP (Model Context Protocol), introduced by Anthropic in 2024, standardizes how AI agents communicate with external tools and services.

Instead of tightly coupling API logic directly inside agents, MCP separates external services into reusable tool servers. This creates cleaner architectures and makes AI systems more modular and scalable.

In my project, MCP servers handle:

  • Weather data retrieval
  • Flight search

Project Architecture

The system is composed of multiple specialized agents:

  • WeatherAgent → Finds the best travel months
  • FlightAgent → Retrieves available flights
  • HotelAgent → Ranks hotels semantically
  • ItineraryAgent → Generates AI itineraries using Llama.cpp

These agents can be orchestrated in two ways:

  • A classic SupervisorAgent
  • A graph-based workflow using LangGraph

LangGraph Workflow

Weather Node
    ↓
Flight Node
    ↓
Hotel Node
    ↓
Itinerary Node
    ↓
Final Travel Plan

LangGraph makes the architecture easier to extend with:

  • Retries
  • Fallbacks
  • Branching logic
  • Shared graph state
  • Debug logging

Weather MCP Server

For weather intelligence, I used the OpenWeather API.

I generated an API key from:

OpenWeather API Keys

The weather MCP server exposes weather functionality over SSE and allows agents to retrieve climate information without directly embedding API logic inside the agent itself.

Flight Search Challenges

Initially, I explored using the Amadeus Flight API:

Amadeus Developers Portal

However, the free tier had limitations for retrieving and testing flight information during development.

Because of this, I decided to keep a manual flight database and expose it through an MCP server.

This approach still allowed me to:

  • Build the complete MCP architecture
  • Test multi-agent orchestration
  • Develop the LangGraph workflow
  • Simulate real flight search behavior

Semantic Hotel Search

One of the most interesting parts of the project was the hotel ranking system.

Instead of simple keyword matching, I used SentenceTransformers embeddings to compute semantic similarity between user preferences and hotel descriptions.

Example preferences: 

"mid budget hotel near city center with breakfast"

The system combines:

  • Semantic similarity score
  • Price compatibility score

into a final ranking score.

Local LLM with Llama.cpp

For itinerary generation, I used:

  • Llama.cpp
  • A GGUF quantized Llama model

Running a local LLM provided:

  • Offline inference
  • Lower cost
  • Full control over prompts
  • Better experimentation flexibility
